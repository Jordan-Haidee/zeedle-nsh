# Rust UI Implementation Plan

> **For agentic workers:** Inline execution in this session. Steps use checkbox syntax.

**Goal:** Add a Rust implementation of the complete Zeedle NSH interface, make it the directory's default root, retain the TSX entry, and share its audio backend and persisted settings.

**Architecture:** nsh.json mounts a Rust ui::App root. UI components call the existing Music Rust module directly, whose OnceLock backend remains the only audio engine; both UIs use NSH storage and the existing theme file. Rust UI code is split by screen and shared controls, with signals carrying reactive state.

**Tech Stack:** NSH Rust components (nsh-core, nsh-base), Music in src/lib.rs, theme.json, existing Lucide SVG assets.

---

## File map

- src/ui/mod.rs: Rust root component, application signals, initialization, keyboard bindings, playback-state timer, shell, screens, player, editor, and delete overlays.
- src/ui/model.rs: Rust equivalents of the TSX data types plus time formatting, sorting, search ranking, and lyric selection helpers.
- src/lib.rs: add mod ui; and register ui::App as the Rust root; retain Music and its backend unchanged.
- nsh.json: set "root": "ui::App", retain "rust": "." and "theme": "theme.json".
- App.tsx: retain as the standalone TSX entry; no migration or deletion.
